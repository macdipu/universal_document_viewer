READING NOTES
=============

Note 1: Reading PDF
Pages are drawn by PDFium and built only near the viewport. Each page starts as a small image and is sharpened with tiles as you zoom in, so a long report stays smooth on a modest phone. Pinch, double-tap or use the mouse wheel to zoom.

Note 2: Reading Word
A .docx is parsed in a background isolate and reflowed to the screen, or laid out in print pages with their headers, footers and page numbers. Styles, lists, tables with merged cells, images, footnotes and links are all kept.

Note 3: Reading spreadsheets
Excel workbooks and CSV files open in a lazy grid that builds only the cells on screen. Column widths, frozen panes, merged cells, number formats, borders, conditional formatting and notes come from the file itself.

Note 4: Reading slides
PowerPoint decks show one slide at a time with their titles, text, tables and pictures, and a bar to move between slides.

Note 5: Searching
Every reader can search. Matches are highlighted and you can step through them one by one; a scanned PDF without a text layer is detected so the app can say why nothing was found.

Note 6: Resuming where you left off
Each reader reports its position as a small JSON-safe map. Store it however you like, pass it back as initialPosition, and the document reopens on the same page, slide, row or line.

Note 7: Thumbnails
DocumentThumbnails renders a PNG of any document, and of the page a saved position resumes on, so a library screen can show where each file was left.

Note 8: Safety
Office files are checked before they are parsed. Damaged archives, paths that try to leave the archive and oversized contents are refused instead of filling memory.

Note 9: Your own interface
When the ready-made viewer is not enough, use the controller and view for one format and build your own app bar, search field and page indicator around them.

Note 10: Platforms
Android, iOS, macOS, Windows and Linux. The engines are part of the package, so there is no other document plugin or web view to add.

Note 11: Opening a document
One widget, DocumentViewer.file(path), picks the right reader from the file name. PDF, Word, Excel, CSV, PowerPoint and plain text all open the same way, and a typed error says why a file could not be read: too large, damaged, protected by a password or not a supported kind of file.
